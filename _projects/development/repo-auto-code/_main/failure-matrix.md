# Repo-Scoped Scheduled Auto-Code Protocol: Failure Matrix

Every row is fail-closed for the affected lane unless it explicitly says that unrelated lanes may continue. Detection evidence is observable state, not permission to guess.

| ID | Failure condition | Detection evidence | Mutation prohibited | Required state transition | Exact user/controller repair action | Unrelated lanes |
| --- | --- | --- | --- | --- | --- | --- |
| F-001 | Fresh controller chat has no memory | No reconstructed packet/authority from live surfaces | No issue/PR/schedule mutation | `CONTROLLER_TURN` | Re-read repository, parent, children, PRs, reviews, checks, claims, and schedules from scratch | Continue only after repository-wide identity is proven |
| F-002 | Fresh executor chat has no memory | No current packet in chat context | No substantive L1 launch | `HELD` | Reconstruct one complete current ready packet and all bindings; do not infer assignment | Other verified lanes may continue |
| F-003 | Toolkit `repo-auto-code` skill missing or uninspectable | Skill path absent, unreadable, or source cannot be inspected | All setup and runtime mutation prohibited | `INVALID` with `AUTO_CODE_SETUP_INVALID` | Install/repair the skill through its source-owned path, then restart setup; do not imitate it | Other repositories and unrelated lanes continue |
| F-004 | Managed block missing or malformed | Marker pair/version/fields do not parse exactly | Do not replace user content or launch | `INVALID` | Show bounded repair for the exact block; require controller/user reconciliation | Unaffected repositories continue |
| F-005 | Provider, Model, or Reasoning missing | Any routing profile lacks one required editable field | No dispatcher or worker launch | `WAITING_USER`/blocked | User fills every profile; controller rereads and verifies availability | Existing unrelated lanes continue |
| F-006 | One controller schedule paused or deleted | Expected task identity absent or not runnable | Do not recreate or activate tasks automatically | `WAITING_USER` | User manually restores or replaces the named task; controller verifies identity | Executor-only unrelated lanes do not start |
| F-007 | Two controller schedules | Two matching repository controller task identities | No controller mutation or duplicate dispatch | `INVALID` | User disables/removes the duplicate after identity review; preserve audit | Other repositories continue |
| F-008 | Two executor schedules | Two matching executor task identities | No substantive claim or code launch | `INVALID` | User removes the duplicate and proves the surviving task identity | Other lanes continue only if capacity is unaffected |
| F-009 | Multiple PRs without explicit lane selection | More than one enrolled/observable candidate and no parent-order decision | No PR chosen by recency/number/author | `CONTROLLER_TURN` | Reconcile parent order, dependencies, reviews, and capacity; select first eligible queue entry | Independent lanes may continue under capacity |
| F-010 | Conflicting parent queue entries | Parent checklist disagrees with child/PR bindings or has duplicate child lines | No enrolment or selection | `HELD` | Controller repairs the parent from child authority or asks user; preserve chronology | Other independently bound lanes continue |
| F-011 | Partial parent/child/PR update | One of three bodies missing packet/turn/child/PR binding | Packet remains non-actionable | `DRAFT` or `INVALID` | Re-read, complete only unambiguous bindings, or discard the draft without deleting audit | Other lanes continue |
| F-012 | Duplicate packets | Two live packets share a Packet ID or one lane has two ready packets | No executor claim or substantive work | `INVALID` | Controller marks duplicate packets non-actionable, retains audit, and issues one new unique packet | Other packet IDs continue |
| F-013 | Malformed handoff markers | Start/end count/order or required field grammar fails | No packet consumption or redaction | `INVALID` | Repair from the source template; never parse a partial packet by guesswork | Other lanes continue |
| F-014 | Non-atomic claim mechanism | Claim is a comment, timestamp, lease, local lock, or unverifiable store | No L1 launch | `HELD` | Supply a trusted packet-scoped atomic create-if-absent capability; use the exact response defined in `protocol.md` | Other lanes may continue |
| F-015 | Duplicate claims | Atomic read-back reports more than one winner for a packet | No code mutation or automatic winner selection | `INVALID` | Controller freezes the affected lane, preserves evidence, investigates primitive integrity, and supersedes only after unpushed-work review | Other lanes continue |
| F-016 | Body/comment disagreement | Packet ID, turn, child, PR, or head differs between canonical comment and bodies | No action even if one copy says ready | `HELD` | Controller rereads live surfaces and repairs the canonical copy; PR pointer cannot decide | Other lanes continue |
| F-017 | Push without result packet | PR head moved but no matching ETO result exists | No acceptance, G4 reuse, or next packet | `CONTROLLER_TURN`/`HELD` | Inspect commits, author, local work, and authority; require a complete result or user reconciliation | Other lanes continue |
| F-018 | Result packet without matching committed state | ETO claims a commit/head that is absent, different, or unpushed | No acceptance or redaction of evidence | `HELD` | Controller verifies live head and worktree; ask for safe proof or supersede after local-work review | Other lanes continue |
| F-019 | User changes before execution | Live head/diff differs before claim | No stale packet launch | `HELD` | Reinspect every intervening commit/diff; adopt only compatible complete fast-forward with controller authority | Other lanes continue |
| F-020 | User changes during execution | Head/worktree changes while claim is active | No silent overwrite, reset, or force-push | `HELD` | Stop safely, preserve bounded local work, reconcile ownership and rerun affected validation | Other lanes continue |
| F-021 | Canonical `main` movement | Base SHA or controlling architecture moved | No stale implementation acceptance or G4 reuse | `HELD` | Controller reconciles Design Lock/base; issue new G1/G2 or amend assignment as authorised | Unrelated lanes continue if their bases remain valid |
| F-022 | Conflicting architecture | Candidate change contradicts G1/G2 or a newer Design Lock | No implementation broadening | `HELD` | Controller resolves architecture at G1/G2; executor stops and reports exact conflict | Other lanes continue |
| F-023 | Forbidden-scope overlap | Diff touches a path outside assignment or protected surface | Do not stage, commit, or push the overlap | `HELD` | Remove only with user/controller authority while preserving bounded work, or split a new lane | Unrelated lanes continue |
| F-024 | Ambiguous adoption | PR could be eligible but current authority, intent, or history is unclear | No enrolment marker or automated mutation | `MANUAL_ONLY`/`HELD` | User/controller classifies adoption after complete diff, commit, review, and head inspection | Other lanes continue |
| F-025 | Ambiguous user intent | Multiple safe next actions or private context is needed | No guessed issue, PR, or schedule change | `WAITING_USER` | Ask one safe question using `PRIVATE USER FOLLOW-UP REQUIRED`; never request raw secrets | Other lanes continue |
| F-026 | Worktree contamination | Unowned, unexpected, or dirty files overlap the assignment | No reset, delete, overwrite, or broad staging | `HELD` | Preserve files and inspect ownership; user/controller resolves before continuation | Other lanes continue |
| F-027 | Possible unpushed executor work | Claim/result absent but local branch/worktree may contain work | No claim retirement, supersession, or cleanup by time alone | `HELD` | Inspect live head, local commits/diff, claim state, and executor evidence before controller retirement | Other lanes continue |
| F-028 | Pending CI | Required checks are queued or not observable | No acceptance, merge, or new implementation packet | `WAITING_CHECKS` | Wait or request user action; report exact pending checks | Other lanes continue |
| F-029 | Failing CI | Required check fails or is unavailable with a failure status | No claim of pass or merge | `CONTROLLER_TURN`/`HELD` | Include complete failure in next assignment; fix only within authority and rerun affected checks | Other lanes continue |
| F-030 | New review arrives mid-run | Open conversation appears after last sweep | No next prompt, G4, acceptance, merge, or closure | `CONTROLLER_TURN` | Controller performs fresh complete sweep and includes valid finding in next prompt | Other lanes continue |
| F-031 | Closed or merged PR has unresolved review | Review conversation remains open despite PR state | No closure or acceptance based on PR state | `HELD` | Controller inspects open conversations across closed/merged PRs, replies/resolves truthfully or keeps valid remediation open | Other lanes continue |
| F-032 | Required model unavailable | Selected Provider/Model/Reasoning cannot be launched or verified | No substitute, downgrade, or self-escalation | Blocked/`WAITING_USER` | User edits a supported profile or controller reissues authority; preserve exact requested profile | Other lanes continue |
| F-033 | Unsupported subagent capability | Harness cannot enforce requested L2 topology or non-fast mode | No invented enforcement or nested launch | `HELD` | Report unsupported capability and remain root-only or user-selected supported path | Other lanes continue |
| F-034 | Provider capacity exhaustion | Truthful harness capacity is below configured substantive demand | No extra L1 claim or dispatch | `HELD` | Keep default one-worker limit; user may configure more only after harness proof | Already claimed lane remains protected |
| F-035 | Secret exposure | Prompt/evidence contains a secret value, credential, auth header, or environment dump | Stop affected and dependent work; do not repeat value | `INVALID` with `SECRET_EXPOSURE_DETECTED` | Contain and rotate the relevant secret class privately; replace public content only with safe markers and preserve audit | Unrelated lanes continue only after dependency check |
| F-036 | Parent closed while work remains | Parent state is closed while child/prompt/review/UAT/ledger obligation is live | No child closure, merge, or task deletion | `HELD` | Controller reopens/reconciles parent through owner authority and records the obligation; do not silently close child | Other lanes continue |
| F-037 | Final prompt not processed | Completion requested while a live next-worker payload remains | No completion or teardown | `HELD` | Receiving side acts, controller reconciles, then replaces only the transient payload with the exact redaction marker defined in `protocol.md` | Other lanes continue |
| F-038 | Incomplete scheduler teardown | One of the two repository task identities remains active, paused, missing, or ambiguous | No final completion claim | `WAITING_USER`/`HELD` | User explicitly removes both tasks; controller verifies exact repository identity and no other repo was affected | Other repositories must remain untouched |
| F-039 | Duplicate controller/executor packet comments | Multiple comments claim canonical status for one turn | No lowest-ID or timestamp winner | `INVALID` | Controller selects one canonical record by explicit authority, preserves all evidence, and republishes a unique packet | Other packet IDs continue |
| F-040 | Final review sweep skipped | G4/acceptance/merge/closure is attempted without complete current review inventory | No progression or resolution | `CONTROLLER_TURN` | Run the complete open-conversation sweep across open, closed, and merged PRs and disposition each finding | Other lanes continue |
| F-041 | Atomic claim create-if-absent returned false or read-back mismatched | `created: false`, `verified: false`, or repository/child/PR/Packet ID/run/head differs on exact read-back | No L1 launch and no automatic takeover | `HELD` | Controller inspects the live head, claim state, GitHub evidence, local work, and possible unpushed work before retiring/superseding; issue a fresh packet only after reconciliation | Other lanes continue |
