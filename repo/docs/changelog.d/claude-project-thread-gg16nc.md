### Fixed

- The merge hold now judges a shell command by every real folder it may run in, not only by its text, and refuses by default: the starting folder always counts (a comment, a pipeline part or a background job can drop a `cd`), every folder a `cd` in it could reach counts too, and a folder the command does not spell out (`cd -` with no move before it, `~-`, `$OLDPWD`, a wildcard or a substitution) or a move it does not follow (a move word behind a prefix such as `X=1`, `!`, `if`, `time` or `command -p`; a `CDPATH`, `HOME` or `OLDPWD` setting; an alias) counts as Toolkit's own folder. Nested shells, `eval` and `trap` actions are read wherever they stand. Inside Toolkit's user-state folder nothing runs; in Toolkit's own folder only listing, reading, changing folder, read-only git and running a script file with node pass, with no wildcards, variables, substitutions, quotes, escapes, redirections or `..`; deeper in Toolkit's folder, a word naming user-state, a wildcard, brace, variable or substitution, a path back up to Toolkit's folder, or code the shell runs in itself from a file (`source`, `.`, a PowerShell script) is refused. Line continuations are joined as the shell joins them, and in PowerShell a backslash stays a folder separator. Links, junctions and letter case on Windows cannot hide the folder, a command too long to read is refused there, and the reader takes time in step with the command's length.
- A push after more than 16 folder changes is judged in a folder Toolkit cannot see, so a push to any branch there is refused, and the push reader no longer slows down on long chains of folder changes.
- A push to the default branch through `--git-dir` or a `GIT_DIR=` prefix, or split by a line continuation, is now judged against the repository it names, so it is held like any other default-branch push. A `GIT_DIR` set earlier in the command (`export`, `$env:`, `set`, `declare`) is judged beside the folder's own repository, since it may never reach git. A named git folder the reader cannot read (a wildcard, a substitution, an unknown variable) is judged as the folder's own repository, and past 16 `GIT_DIR` settings in one command a push is refused, so many settings before many pushes no longer take minutes.
