### Changed

- **Weaknesses filed whenever the summary shows them:** when refresh governance (or toolkit governance) shows the summary and lists a problem in the repository's own files for its controller, such as a required job that a failed job it waits for can skip, it now files that problem once as a native child task under the programme parent, even when no GitHub setting has drifted and so there is no yes to answer. Each line for the controller names its task ("Filed as #N under #P"), names it again while it is still open instead of filing a second one, or says why it could not be filed so the controller files it. Before, filing ran only after a settings yes or a turn-on finish, so a repository with its settings already in step never got the task.
- **Reads stay read-only:** the status and check commands and a `--json` read of the governance questions file nothing, and a run that applies the owner's answer files nothing more (a settings yes still names the tasks through its own finish, as before). Offline and test runs never write to GitHub.
