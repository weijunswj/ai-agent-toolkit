### Fixed

- A merge whose checks are still running no longer ends with the agent's own merge question: the desktop asking line, the guided setup's turn-on step, the governance proposal lines and the safety-gates and merge-card playbooks tell the agent to wait for the checks in one background wait and then run the merge, so Toolkit's merge card stays the only ask. The agent asks only when a check fails or the merge is refused for another reason.
- Right after a governance merge, the default-branch protection check no longer reports that a required check has no producing job when the workflow is on the merged default branch but not yet in the local checkout: it reads the workflows at the merged default-branch commit the binding was read from, never the working tree, and a commit it cannot read here is reported as not checked.
- The governance summary says "Say done when you have run it" when there is one command to run.
- The task auto-merge switch note no longer tells the owner to merge only once every computer and cloud copy runs the new release. It states the effect on older copies, and the terminal names the Toolkit copies read on this computer and says that copies on other computers and in cloud sessions cannot be read from here.
