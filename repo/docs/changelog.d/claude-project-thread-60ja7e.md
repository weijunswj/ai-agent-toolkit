### Fixed

- The merge hold and push check share a plain git command test: one git command, no substitutions even in quotes, and no unquoted shell operators, line breaks or cmd variables. Codex argument-list wrappers are unwrapped first.
- A non-plain line mentioning git, push and a shell or expression runner is refused regardless of target branch. Shell names inside single- or double-quoted text do not count, unless the whole quoted string names a runner (optionally with a path or `.exe`); runners inside substitutions or backticks still count within double quotes. Plain git commands keep the usual default-branch check. Encoded PowerShell commands remain refused unread.
- Quoted shell names in commit messages and search text pass, including `git commit -m "Fix sh script" && git push origin feature`. Accepted false refusals include combined commands such as `bash -c "npm test" && git push origin feature`. Run the push as its own plain git command. Runners without a git push mention, such as `bash -c "npm test"` and `eval "$(ssh-agent -s)"`, remain allowed.
- When Codex names no folder and several working trees are reachable, HEAD is checked in each tree only for a whole line containing one plain git command. Every other unknown-folder HEAD line is refused, including a read before the push or a quoted location command. Absolute folder confirmation and named-branch checks keep their existing paths.
