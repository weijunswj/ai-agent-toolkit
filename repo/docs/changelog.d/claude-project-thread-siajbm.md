### Fixed

- The merge hold now judges a shell command by the real folder it runs in, not only by its text. Inside Toolkit's user-state folder nothing runs; in Toolkit's own folder only listing, reading, changing folder, read-only git and running a script file with node pass, with no wildcards, variables, substitutions, quotes, escapes, redirections or `..`; deeper in Toolkit's folder, a word naming user-state or a path that could lead back up through `..`, a wildcard or a variable is refused, also once quotes, escapes, `$'...'` strings and braces are undone and line continuations joined as the shell joins them. In PowerShell a backslash stays a folder separator. Links, junctions and letter case on Windows cannot hide the folder, and a command too long to read is refused there, or when it changes folder.
- A push to the default branch through `--git-dir` or a `GIT_DIR=` prefix, or split by a line continuation, is now judged against the repository it names, so it is held like any other default-branch push. A `GIT_DIR` set earlier in the command (`export`, `$env:`, `set`, `declare`) is judged beside the folder's own repository, since it may never reach git.
