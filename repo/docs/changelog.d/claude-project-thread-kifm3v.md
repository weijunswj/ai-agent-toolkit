### Fixed

- **Issue-close guard reads more hidden shell shapes:** where PowerShell may run a command (its own tool, an unknown shell or Codex Bash), a data command's script block holding a guarded gh write now counts as running when the same statement pipes it on to any further stage (`|% Invoke`, `| foreach Invoke`, `| Where-Object { $_.Invoke() }`, `| Out-String | iex`); even a harmless `| Out-Null` after such a block is refused. `iex` text built by a `$(...)` substitution, a character cast or a method call that mentions gh or its pieces is refused, and so is a script block made from such text with `[scriptblock]::Create` or `$ExecutionContext.InvokeCommand`.
- **POSIX `-c` scripts that reassemble their arguments:** a script that expands its positional parameters (`$0` to `$9`, `${n}`, `$@`, `$*`) is read with them put in place, so `sh -c '$2 $1' x 'issue close 1' gh`, `sh -c '$1$2' x g 'h issue close 1'` and `sh -c 'g$1 issue close 1' x h` are refused, on every shell, as is any such call whose arguments in some order spell a guarded gh write.
- **Two readings of escaped quotes compare writes, not counts:** on Codex Bash and unknown shells, text with backslash-escaped quotes is refused when its PowerShell reading runs a guarded write (by noun, verb and target) that the judged reading does not see, not only when it sees more writes.
- **Timing tests:** the shell-reader timing comment now names scheduler preemption as the cause of the old flake, and the closing-reference timing uses the same longer samples.
