# Skill Safety Matrix

This matrix is the maintenance review surface for deciding whether a skill should be used, extended, or split into a new canonical skill surface.

It does not grant permission to run risky actions. Repo rules, skill instructions, explicit user approval requirements, and source-of-truth ownership still apply.

## How To Use

- Before adding a new skill, adapter, template, or contract, compare the proposed use case against the existing rows.
- Prefer extending an existing skill when the trigger, safety boundary, source model, and validation path fit cleanly.
- Create a new Toolkit skill directly under `skills/<skill-name>/` after Skill Creation Center review, with coupled contracts, runtime, tests, and docs directly under canonical `repo/**` paths, only when the use case has a distinct trigger, domain, risk boundary, provenance requirement, local assets, or validation path. Do not add an intermediate ownership, publication, or generic synchronization layer.
- For third-party skills, skill packs, GitHub skill repos, or adapted external agent material, run `skill-product-review` before copying, installing, executing, or converting anything.
- The separate generic `skill-product-review` product retains its publication and anti-drift semantics; it is not part of Toolkit operation.

## Legend

| Risk Class | Meaning |
| --- | --- |
| Low | Instruction or review workflow with no default local writes, no bundled executable tooling, and no live-system mutation. |
| Medium | Local repo writes, local processes, generated surfaces, third-party provenance, or optional tools may be involved. |
| High | Credentials, workflow JSON, live systems, external service writes, CI/CD, Docker, deployments, or destructive impact are plausible if misused. |

## Description Review Notes

OpenAI/Codex metadata permits implicit discovery for the 14 products admitted by `repo/tests/fixtures/skill-routing-cases.json`. `codex-ssh-hostinger-coolify-setup-maintainer`, `controller-bootstrap` and `release-readiness-audit` remain explicit-only. Implicit discovery never grants mutation or live-system authority.

Watch these trigger boundaries when editing descriptions:

- `n8n-safety-router` should stay the broad mandatory n8n safety gate.
- `n8n-environment-setup` should stay focused on environment setup, the localhost/ngrok dev path, the separate production Cloudflare Tunnel path for local/CGNAT machines, hosted n8n Hostinger Coolify VPS notes, [official n8n Skills](https://github.com/n8n-io/skills) setup and the n8n API.
- `n8n-workflow-transport` should stay focused on helper templates and repo/live hygiene.
- Test-only n8n workflow fixtures must not regain a public product, route, install surface, or reusable-template claim.
- `skill-product-review` should stay focused on third-party product review and approved provenance-preserving publication, not general coding work or Toolkit topology.
- `codex-ssh-hostinger-coolify-setup-maintainer` should stay focused on Hostinger VPS plus Coolify deployment setup, security checks, intrusion-signal review, maintenance alerts, evidence-based maintenance, and incident response, not generic DevOps or n8n app deployment inside Coolify after the platform exists.
- `release-readiness-audit` should stay a guarded final readiness audit and remediation loop, not ordinary implementation, narrow code review, deployment execution, or an implicit full-repo scan.
- `local-ai-safety` and `self-hosted-service-safety` should stay small, review-only, and scoped to setup/exposure risk.
- `github-program-reconciler` loads on its own; the reconciler, state documents, managed blocks and sub-issue links require `.github/toolkit-programme.json`, while Toolkit-governed rules and their issue records are unchanged in 3.9.0. Repositories without the governed block get no governed issue writes, only coding-governance gates, subagents and portable skills; global rules still apply, including PRs after requested edits and task issues when the user asks to add one. Its writes stay limited to native sub-issue links, its own managed blocks and the bound private store, and it never closes, deletes, merges or mutates reviews.

## Maintenance

- Update this doc when a skill is added, removed, renamed, materially changes trigger scope, gains tools, changes provenance, or changes approval boundaries.
- Keep `repo/docs/FOR_AI_AGENTS.md`, README skill tables, and `repo/contracts/agent-rules/toolkit-skill-routing.md` aligned when skill routing changes.
- Run `node --test repo/tests/skill-routing.test.cjs` after matrix edits.
- Run `node repo/scripts/validate-toolkit.cjs` before pushing.
