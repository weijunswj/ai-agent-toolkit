# Toolkit Controller: gates
Part of the [Toolkit Controller](../CONTROLLER.md); it binds like that file.
## Gate lifecycle and acceptance
- Gate states: ACTIVE, WAITING_OWNER (question/UAT), INTERRUPTED, SUBMITTED, RETIRED. Questions/UAT leave G0/G1 unfinished in the same assignment; checkpoints normally continue the session. Retire completed accepted gates; never reuse them. Exactly one recoverable successor continues an interrupted gate. Consume returns once by identity; repeated launch requests reuse their session; clearing blockers releases held work; report authorised work without a live session as stranded. Fresh gates/corrections inherit recoverable state, not reset budgets or rediscovery. Preserve transcripts/required resources before supported archiving; logical retirement suffices without native archive. G1 never launches or runs its own G2.
- At admission split acceptance: owner UAT only for final-product steps (global rules), objective acceptance (CI, G2) for the rest; with no such step record NOT_REQUIRED. Missing authority never waives a needed UAT; it runs after merge on the installed build; at that merge record UAT PENDING on each `Refs` task, open until it passes (gate rules). Keep UAT_READY inside G1; in-scope feedback needs no readmission. A new SHA alone does not invalidate UAT: with impact evidence record UAT_RETAINED, UAT_PARTIAL_REQUIRED or UAT_FULL_REQUIRED.
- **Models before building:** a RISKY feature touching authority, custody, state machines or host configuration gets the gate rules' invariant model and closure matrix as a G0 deliverable; G1 tests it table-driven, G2 reviews against it, and a recheck that finds a missing path returns the matrix to G0-level revision.
- **Scope confirmation:** a child's G0 live-scope summary (decision-trace playbook) is the spec only once the owner confirms it; record that as a `SCOPE-CONFIRMED` comment on the child.
- G2 tests scope, execution, security and evidence, not source style. Classify findings against agreed acceptance: ship blocker (High or Medium, gate rules), follow-up (Low; one record per PR, joining an outcome child), new Later/optional outcome, unsupported/duplicate; return the coherent blocker set to the builder. G2 stays adversarial on every reachable path inside the release brief's frozen supported host/environment matrix (input: the repo's supported-OS policy) and agreed invariants. Plausible supported-path violations or critical missing proof block. Send unsupported/new environments to the owner for classification, never expand Core. Inventory and fix demonstrated boundary families once; fresh rechecks target fix commits, corrected families and dependent invariants. Optional improvements need owner admission. Use fresh G1/G2 contexts for corrections/rechecks with the same selected members (fresh-context, family-closure and delta-review rules are in the gate rules); get functional evidence after the last material change, never restart all gates for one line. After authorised integration/activation, read back the reviewed payload in a fresh installed session. Close as completed, without asking, only children the governed issue rule completes; retain owners for later commitments.
### Human-readable product and operational text
For new/changed human-facing work, G0/G1 name the audience; G1 makes names, labels, instructions, errors, notifications, canvases and explanations readable without programme history; G2 checks. State purpose, trigger, inputs, changes/outputs, failure/recovery and operator action; use business-language labels, technical IDs in machine fields. For n8n include a meaningful workflow name, readable major nodes and maintained canvas overview or equivalent operator docs; expressions, credentials and live changes need their own authority. `G0`, `G1` and `G2` remain valid where meaningful; no unexplained programme/version/migration names. Keep necessary versioned contracts/historical receipts. Each retained exception names its current consumer, accountable owner, present behavioural necessity and removal condition; remove it then. Fix changed-path clarity in existing work/rechecks, never a new gate or wider worker/repo scope.
