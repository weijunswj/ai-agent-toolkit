# Toolkit Controller: evidence, progress and finish
Part of the [Toolkit Controller](../CONTROLLER.md); it binds like that file.
## Evidence, progress and finish
- Executors publish concise authorised progress and screened private evidence directly: fresh expected-head/conditional writes, minimal edits, unrelated content preserved, independent readback. Keep conflicts/unknown outcomes in PR/evidence store. Transport failure is no implementation defect; republishing unchanged bytes consumes no correction.
- Finish authorised work before stopping, as the global rules' Shipping section says; a genuine hold stops only its dependent steps.
- Reuse the user-selected private evidence store; a private `TRANSPORT-*` Git repository is only the recommended default when no store was previously selected. Verify identity, privacy, access and consumer retrieval through its backend; hold unsupported capabilities. Session folders are never custody (governed block).
- **Custody without ritual:** in a Git evidence store the commit is the manifest, and a successful push plus one fetch is the read-back. Separate manifest/read-back only for non-Git stores and sole copies. Work in shared/scratch folders; archive once at gate end: final report and what later readers need, not every revision. Full run stream only for FAIL/dispute; else report and cost line suffice.
- Scratch follows the global rules; after a lane's PR merges, remove its worktree (`git worktree remove`, then `git worktree prune`) and its branch (`git branch -d` once `git merge-base --is-ancestor` shows it merged), never `--force` or `-D`; keep and report a dirty, locked or unmerged worktree, one with ignored files (`git status --ignored`: removal deletes them) and a closed-unmerged PR's branch; and delete throwaway test scratch at run/turn end (a run stream or log kept for a FAIL or disputed verdict is evidence, never throwaway). Delete scratch once its report and kept evidence are stored and read back; never delete the only copy, user data, active or UAT resources or unresolved evidence.
- **Merge trains:** two or more merge-ready PRs (G2 PASS at an exact head, green CI) land as one train, chosen by the controller unasked; a lone ready PR merges alone, and an ejected member rides the next train once fixed and delta-reviewed: `node repo/scripts/toolkit-merge-train.cjs build`, then `verify`, one train PR whose body is `body`, one CI run, then `land` and one merge of the head it names (`--match-head-commit`). Each member boards at its reviewed head as its own merge commit, so it shows as merged with its own review; one bump at the highest level. Never hand-fix a train: a conflict, moved head or failed bump ejects that member; red CI splits it (`split`) until the culprit is out. RISKY members each need the owner's typed OK; the train's tier and UAT line are its strictest member's. While a train waits on CI, the next combines on top (`--onto`) and rebuilds on main once it lands.
- **Promises:** record every controller/executor promise to the owner ("I'll ...") at once, with its trigger (merged PR, PASS file, shipped version), where every harness can read it: the PR or the programme issue comments when ENABLED, else the evidence store. A Projects controller keeps a plain list in project memory instead (Projects skill), read by its hourly nudge. Remove an item only when done. Merge/review-PASS/shipping briefs carry every event-keyed follow-up; sessions end with a checklist (done, or "controller:" plus what remains) and the controller acts on unchecked items the same turn; report an overdue item under **Overdue promise:** and act, never silently drop it.
- Native coverage: Codex/Claude Code on real selected paths; Antigravity portable skills only. Gate custody (session identity, turn-end checkpoint hook, completion modes, handover): [host contract](../docs/HOST-CONTRACT.md). Qualify entry, route/effort, permissions, recovery, cancellation, EOF, output, exit, privacy and Windows behaviour. Align source/cache/profile/version; preserve rollback. Unavailable exact routes stay outstanding, never substituted or synthetically passed. The directive's host matrix and acceptance cases are not claimed implemented or qualified here.
