# Toolkit Controller: design principles
Part of the [Toolkit Controller](../CONTROLLER.md); it binds like that file.
## Design principles
- **Binding:** the owner's standing design principles. They bind every controller, harness skill, project line and brief, which may add to them but never relax them; judge every plan, review and merge against them. A clash goes to the owner as a decision; a new principle needs an owner record (numbers below are the owner decision records on the programme parent issue).
- **Development base:** the global rules' Development Principles bind every controller too, with their records: tests first (330, 332, 500, 808), fast CI (391, 865), grouped changes (owner, 14 November), slim and no scraps (041, 459, 460, 719, 905), platform first (215, 235, 409, 515, 516), never silently wrong (393, 509, 510). This page adds the controller's own.
- **Plug and play:** the plugin carries the guidance. A governed repository gets a Toolkit file only when needed (its binding, Toolkit CI checks); an ungoverned one gets none (300, 396, 719, 723).
- **Owner-only acts:** merges, deletes, real keys and irreversible acts need the owner's OK; the repository's task auto-merge switch On counts (Standing approvals in the core; 172, 885, 905). Permission settings change only on the owner's explicit ask, with a one-paste command (901).
- **Git hygiene:** merge commits only; no force-push or history rewrite; the owner's commit identity; no AI attribution (global rules; 215, 669).
- **Controller is the brain:** it does the whole job, gets what it cannot reach through an executor or a paste-back prompt, and says what its harness cannot do (core; 438, 474).
- **Local base:** local Toolkit is the base every harness inherits; a harness adds only its own mechanics, and a clash goes to the owner (707).
- **Cloud first:** work runs in the cloud unless it needs the owner's computer; no computer scheduled tasks; new scheduled work joins an existing task first and stays a short prod (442, 670, 756, 852, 861).
- **Owner reads and clicks:** agents do all linking, moving and archiving; everything that closes gets a closing comment (463, 700).
- **Finish fast:** ship the biggest coherent batch; lanes never idle; merge trains never wait (054, 321, 885, 888).
- **Plain owner posts:** plain words in the owner's time zone; "(my pick)" is the best option on the evidence, not the owner's leaning (198, 219, 606).
- **Free first:** no paid plans; reviews run on the subscription; speed comes from free fixes (737, 865).
- **Host-local talk:** a host never mentions another host's Toolkit state unless asked (241).
- **Per-repo governance:** governance runs only for github.com repositories, set per repository, never globally (246, 362).
