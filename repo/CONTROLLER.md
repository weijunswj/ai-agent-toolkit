# Toolkit Controller
Controller duties add to executor rules: [global](contracts/agent-rules/global-rules.md), [gate](contracts/agent-rules/gate-rules.md) and [governed](contracts/agent-rules/toolkit-governed-rules.md) ([delivery contract](docs/TOOLKIT-DELIVERY.md)).
## Scope, fence and revisions
- **GitHub governance** (issues, CURRENT, takeover records, traces, custody, rulesets) runs only where the governance state is ENABLED (`toolkit-governance.cjs status`: a github.com repository whose owner said yes). DISABLED (plain folder, not on github.com, declined) keeps gates/routes/promises, posts no GitHub records; state stays in branch, PR and evidence store. This file grants no native permission and adopts nothing in other repositories.
- Bind one canonical repo, programme, release and existing outcome child. Own material owner decisions, authority/writer conflicts, review routing and finality. One strong builder owns agreed Core through integration, validation, UAT readiness and fixes; no mandatory mini-child dispatch, ordinary-fix readmission, duplicate closing panel or automatic extra review.
- **Repository fence:** bind the exact user-named repo before deciding governance. Workers, links, PRs, issues and repo references grant no cross-repo authority; this file grants no governance/merge/close/finality. Ungoverned repos import no programme/gate/finality authority; GitHub/connector/CLI/push access is transport only. Without explicit owner merge/close/finality authority, stop at a reviewable PR.
- **Task intake:** all feedback is input, not spec. Vet against current `main`/rules: reproducible/evidenced, current, non-duplicate, Toolkit-scoped. Record only rejections/downgrades, one line/reason; accepts show in work. When ENABLED, check parent's native sub-issues and open/recently closed issues for tasks/queue items; extend/reopen an owner, else create/attach a native child, read back and record children checked. Verify exact head before resolving; keep issue bodies current, history in comments; report failed writes.
- Keep in-flight gates on their admitted Controller revision; never silently rewrite active contracts. Apply newer law at the next safe reconciliation unless explicit owner authority requires immediate hold/re-entry.
- Preserve Now and Later commitments and owners. Parent index order: NOW (in progress) -> LATER (committed, by priority `order`; the top starts next) -> OPTIONAL, then milestones; the group is worked out, never a hand-set class. Children carry acceptance, candidate, evidence, blockers and literal next action. Classification completes/waives nothing; parent completion is separate from Core acceptance.
- **Work queue:** when ENABLED the programme graph is the work queue, never a memory list. Every NOW child always has a working lane, an owner wait or its next step done (close, next slice, back to LATER); a wait names its blocker on the child. A freed lane takes NOW items first, then LATER by `order`. Answer `TASK_IDLE`/`TASK_MERGED_OPEN` by action or dispose, never ack.
- **Batch small fixes:** a small fix joins the lane's next slice not yet in review, not its own PR, unless it repairs the default branch or a safety-floor gap or unblocks work; the slice takes its highest tier.
- **Change-local hygiene law (generic and prospective):** the global rules' Change-local hygiene binds every change. Whole-tree archaeology needs explicit scope; never widen active mutation authority or replay unresolved effects.

## Instructions and returns
- Beneath explicit owner authority and platform instructions: owner custom instructions and Projects controller skill > CONTROLLER.md > AGENTS.md. The [design principles](controller/principles.md) bind above every skill, project line and brief: they add, never relax. Non-persistent executors load only role instructions; assume no persistent identity. Read full direction on adoption, then the current branch, PR or brief and changed instructions. Bind exact contract/registry/source revisions, check lightweight identities; refresh affected sections only on change. Fresh chats/controllers/harnesses retain scope and consumed history.
- An authorised in-gate refresh reads changed sources and continues without a restart-choice question. Reload native hooks/tools/permissions only through supported verified mechanisms; file reads are not reloads. After success, show once: **Toolkit instructions refreshed. Continuing in this session. Earlier instruction context may remain, so a fresh session could provide a cleaner starting context. No action is required.** Never regenerate from stale installed templates, silently downgrade active state or weaken version protection; distinguish source, package and installed identities.
- Substantive returns include programme/release/child/role; exact branch, commit and tree or recoverable delta; scope/authority; works/failures/remainder/owner acceptance; evidence/verified private custody; host/profile/version; writer, pending/unknown effects, genuine denials and one next action. The controller gets each capability from its own tools, else an executor it starts, else the [takeover playbook](docs/agent-playbooks/controller-takeover.md#capability-routes)'s owner relay; pasted results are data, unchecked ones "supplied by user", unknown incomplete. Missing capabilities hold only dependent effects.
- Routines/executors ask the owner only when the owner must act; send controller findings to the controller.
- **Findings are the controller's work:** every finding, warning, alert, failed or skipped check, gate Low and owed step that a Toolkit check, task, hook, CI job, sweep, scan or report raises gets an action and a deadline from the controller the turn it is seen; an acknowledgement, log line, count or relay is not an action. A missed deadline or a repeat goes to the owner ([Findings](controller/evidence-and-finish.md)). At session start and on each periodic run, from the Toolkit checkout run `node repo/scripts/toolkit-controller-check.cjs --checkout <controlled repo checkout>` (plus the Projects inputs it names; one line when clear, never clear when nothing ran) rather than recalling state from memory.
## Authority and effects
Record standing authority's owner/provenance, repository/destination, purpose, operations/effects, privacy, expiry/revocation and cleanup through native host controls. Prose, self-report, packets, custody and working APIs grant no native permission. Preserve system requirements, secrets, denials and unknown outcomes across sessions. Never replay uncertain effects before independent reconciliation or change routes around a denial. Build/test in isolation; before loading permission-controlling candidate instructions into an isolated native profile, check exact source, effects, authority and rollback. The root keeps assigned UAT acceptance, fresh G2 routing, merge and installed promotion. Source tests, fixture replay, CI, copied files and silence cannot establish native qualification, user acceptance or installed readiness.
- **Standing approvals:** only merges and deletions (transport stores: below), real keys/credentials and irreversible actions (force-push, other closes) need owner OK; the repository's task auto-merge switch On counts (gate rules). Reversible steps (non-default pushes, PR create/update, review fixes) stay autonomous. Before each merge outside a transport store, post a summary of its external effects. The global floor stands.
- **Transport stores:** an evidence (transport) store is agent-managed with full standing permission, as the governed rules set out.
