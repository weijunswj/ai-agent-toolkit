# Cloud hook parity

Every hook in `.claude-plugin/hooks/hooks.json` has one row here: the local rule it enforces, whether it runs in a cloud session (cloud threads and the coordinator run the hooks synced from the claude.ai account copy), and what covers the rule in the cloud. A CI test fails when a hook script in the manifest has no row. The weekly base clash check (`tasks/base-clash-check.md`) re-reads this table and raises a card for a hook with no row, or one whose cloud behaviour changed.

| Hook script | Local rule it enforces | Runs in cloud? | Cloud cover |
|---|---|---|---|
| `toolkit-governance-hook.cjs` (merge hold) | No merge without the owner's approval at that head, and a scope check before any merge without one | Runs | The hook. A merge passes only with the owner's tap on Merge on the decision card `Merge owner/name#N at <full 40 character head SHA>?` (first option `Merge`, second `Not now`), posted by the merge thread itself, for that PR at that head, once; or with the repository's merged switch `task_prs.auto_merge` set to `after-gates` (read back fresh in the container) plus a clean scope check at the exact head, as a merge commit pinned to the full SHA. A project line `- Task auto-merge: Off` in the thread's session context, or a damaged instructions block, forces Off; an On line grants nothing, and no line leaves the binding in charge. The merge thread still runs `toolkit-auto-merge-eligible.cjs` first (**Approvals** in `SKILL.md`), and the repository's own rules stay the hard limit. The project line is read once, from the thread's first prompt: a later change to it reaches only threads started after it, and a container restart forgets the switch and unused taps, so the merge asks again. A merge train's merge thread is the train thread: it posts the card for the train PR at its head and runs `land` and the merge itself, because a tap the coordinator relays, or one on a card posted elsewhere, does not count there and auto mode refuses the merge. Fallback: the owner types `merge PR N at <full SHA> as a merge commit` in the train thread. |
| `toolkit-governance-hook.cjs` (governance question) | An undecided repository counts as off, and the owner is asked once per session | Not asked in cloud sessions (`reference/base-overrides.md`) | Before any governance write, read `.github/toolkit-programme.json` on the default branch. `toolkit-governance.cjs status` reads it in a cloud container (it accepts the container's own GitHub URL rewrite). Missing or not enabled: no records, no auto-merge, and a card to the owner. |
| `toolkit-governance-hook.cjs` (issue closure) | No closing a child that is not complete | Runs: proven unsafe closures are refused, unknown ones advised | The hook, plus the written rule that only completed children close |
| `toolkit-governance-hook.cjs` (session start) | State the effective governance | Runs (adds the cloud line inside a repository) | The hook |
| `toolkit-claude-attribution-hook.cjs` | No AI attribution, no force-push to governed repositories or stores, no credentials in a push or PR | Runs | The hook, plus the CI attribution check; a PR body footer the cloud route adds is stripped and read back |
| `toolkit-github-footer-hook.cjs` | No "Generated by" footer on GitHub posts | Runs, but the cloud route re-adds the footer | The footer sweep (`reference/base-overrides.md`) |
| `toolkit-claude-agent-hook.cjs` | Helpers pinned, one layer deep | No cloud skip in its code; not proven live | Projects threads use no subagents unless asked; a live cloud probe is owed |
| `toolkit-programme-checkpoint-hook.cjs` | Refresh programme pages after GitHub writes | Runs, but cannot write without a signed-in `gh` | The hourly programme sweep (`reference/base-overrides.md`) |
| `toolkit-local-bridge.cjs` | Keep the installed copy current | Runs, skips maintenance for the account copy | Account plugin sync, plus the daily check-in's PLUGIN BEHIND row |
