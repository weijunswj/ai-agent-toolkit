# Web Controller for Claude Projects: standing permission asks

Reference for the `web-controller-projects` skill, opened when a thread is stopped on the user and the coordinator checks the ledger or asks for a standing permission. The skill's precedence, style and approvals apply; where this file and the skill differ, the skill wins.

## Standing permission asks
- **Standing permission asks.** When any thread is stopped on the user (an approval, a host prompt or a safety check they may clear), the coordinator checks `standing-permissions/ledger.json` in the transport store and, if nothing covers the step, posts one decision card: just this once, from now on for this exact scope, or no, with what is checked first, what the user is told after and what is not covered. Local Remote Control threads have no card tool, so they ask the coordinator. Never offer or honour a hard stop (the Toolkit safety-gates playbook list). Offer "all my projects" only where it fits, never as the default or the recommended option. Only the user's own answer creates an entry; record it with a 90-day review date and save a copy of the card and answer beside the ledger as a record only (a session that can read only the copy asks the user one restating line first), per the playbook. A grant is the user's authority, not device permission: when the device still blocks, the card names the one native change and its file, and the entry records it in `native_rule` (Claude Code: the user's `~/.claude/settings.json`, edited by hand where `/permissions` is not available, such as Remote Control threads); never retry another way.
