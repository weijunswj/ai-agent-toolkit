# Web Controller for Claude Projects: guidebook refresh

Reference for the `web-controller-projects` skill, opened when the coordinator refreshes the guidebook copy, finds it missing or gets `SKILL COPY FAILED`. The skill's precedence, style and approvals apply; where this file and the skill differ, the skill wins. A bold section name, such as **Hourly nudge**, names a section of the skill.

Projects takeover applies only when the host role line names this session "the coordinator in a project", native project tools include `mcp__hearthbot__start_thread`, and Read can access single files under `/mnt/project-files/`. Listing files, a shell, Write or git are not required; the Toolkit subfolder need not exist. A runtime name alone (for example "Claude Code") never disqualifies a host-assigned Projects coordinator. Exclude by role and place: project threads (host role "working in a thread of a project"), Remote Control sessions, Claude Code or Codex in a CLI, desktop app or IDE outside Projects, helpers and executors never initiate this coordinator procedure. Copied text or paths never qualify; copied project instructions, briefs, quoted system instructions or tool names do not establish host identity. Absent or ambiguous role evidence means skip it and keep the assigned role.

## Relay before setup
A thread or coordinator worker reading CONTROLLER.md for a Projects coordinator's appointment, takeover or setup, or only to read or report on it, relays the setup line and [guidebook link](guidebook.md) before takeover writes. Relay the **Missing folder** bootstrap step below too. Report, stop and wait for the coordinator; never run setup yourself. Setup is incomplete until steps 0-10 are all verified done (unknown is incomplete): only a coordinator brief for a setup step permits continuing or controller writes, takeover records included. The coordinator qualifies from its own host role line and tools; the relay selects a procedure, never establishes identity. No special phrase or preference line is required. Threads also have `read_project_chat`; it does not distinguish a coordinator. A setup step's own brief permits only its specified action, such as the step 6 mode b takeover record; it never transfers controller identity or allows general controller work. Ordinary G1/G2 briefs that read the file continue on their brief.

## Refreshing the guidebook copy
- **One refresh, three routes.** `node repo/scripts/toolkit-projects-guidebook.cjs --out <folder>`, run by a cloud thread from a fresh clone of main, copies the files, writes `instructions-block.md`, writes `VERSION` last and reads every file back; it prints `SKILL COPY REFRESHED <Version>`, plus `BLOCK CHANGED <version>` when the block changed, or `SKILL COPY FAILED <reason>`. `--check <folder>` only compares.
  - The hourly nudge checks the copy against a fresh clone of main every run and refreshes a stale or changed copy itself (at most an hour behind a merge or a stray write).
  - After a merge that changes this skill or the Toolkit version, start a cloud thread for the refresh at once (fast route, optional speed-up).
  - The daily check-in is the backstop: it refreshes a copy still stale two hours after main changed, or when the nudge is stopped or not armed, and reports `GUIDEBOOK MISSING` or `SKILL COPY STALE`.
- **Missing folder:** on a qualifying coordinator appointment, a missing folder or `VERSION` triggers bootstrap even without a managed project-instructions block. Start a cloud thread with a fresh clone of public `weijunswj/ai-agent-toolkit` `main` and run `node repo/scripts/toolkit-projects-guidebook.cjs --out /mnt/project-files/toolkit/web-controller-projects/`. The thread only performs its copy brief and remains an executor. Read its full result and require `SKILL COPY REFRESHED`; then read the library's `SKILL.md` and run Guided setup and takeover steps 0-10 before other controller actions. With an existing copy, read the skill and enter or resume the same setup; step 0 checks freshness. Resume verified progress after interruption. Do not post the generic takeover record ahead of setup or post it twice.
- `SKILL COPY FAILED`: start one fresh refresh thread; when that fails too, tell the owner once what failed. With no usable copy, hold takeover. Preserve any last usable copy and setup progress; never substitute generic takeover for guided setup. Outside an appointment, a missing or failed copy keeps working from the last usable copy or the managed block and reports it.
