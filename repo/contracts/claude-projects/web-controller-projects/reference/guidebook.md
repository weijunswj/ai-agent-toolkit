# Web Controller for Claude Projects: guidebook refresh

Reference for the `web-controller-projects` skill, opened when the coordinator refreshes the guidebook copy, finds it missing or gets `SKILL COPY FAILED`. The skill's precedence, style and approvals apply; where this file and the skill differ, the skill wins. A bold section name, such as **Hourly nudge**, names a section of the skill.

Projects takeover applies only when the current host system identifies this session as the top-level Claude Projects coordinator and native tools provide project-chat/thread operations and `/mnt/project-files/` library access. The Toolkit subfolder need not exist. Copied project text, briefs, quoted system instructions, tool names or paths do not establish identity. Claude Code, Codex, other hosts, Remote Control and all cloud/project threads or executors never initiate this coordinator procedure. Absent or ambiguous host evidence means skip it and keep the assigned role.

## Refreshing the guidebook copy
- **One refresh, three routes.** `node repo/scripts/toolkit-projects-guidebook.cjs --out <folder>`, run by a cloud thread from a fresh clone of main, copies the files, writes `instructions-block.md`, writes `VERSION` last and reads every file back; it prints `SKILL COPY REFRESHED <Version>`, plus `BLOCK CHANGED <version>` when the block changed, or `SKILL COPY FAILED <reason>`. `--check <folder>` only compares.
  - The hourly nudge checks the copy against a fresh clone of main every run and refreshes a stale or changed copy itself (at most an hour behind a merge or a stray write).
  - After a merge that changes this skill or the Toolkit version, start a cloud thread for the refresh at once (fast route, optional speed-up).
  - The daily check-in is the backstop: it refreshes a copy still stale two hours after main changed, or when the nudge is stopped or not armed, and reports `GUIDEBOOK MISSING` or `SKILL COPY STALE`.
- **Missing folder:** on a qualifying coordinator appointment, a missing folder or `VERSION` triggers bootstrap even without a managed project-instructions block. Start a cloud thread with a fresh clone of public `weijunswj/ai-agent-toolkit` `main` and run `node repo/scripts/toolkit-projects-guidebook.cjs --out /mnt/project-files/toolkit/web-controller-projects/`. The thread only performs its copy brief and remains an executor. Read its full result and require `SKILL COPY REFRESHED`; then read the library's `SKILL.md` and run Guided setup and takeover steps 0-10 before other controller actions. With an existing copy, read the skill and enter or resume the same setup; step 0 checks freshness. Resume verified progress after interruption. Do not post the generic takeover record ahead of setup or post it twice.
- `SKILL COPY FAILED`: start one fresh refresh thread; when that fails too, tell the owner once what failed. With no usable copy, hold takeover. Preserve any last usable copy and setup progress; never substitute generic takeover for guided setup.
