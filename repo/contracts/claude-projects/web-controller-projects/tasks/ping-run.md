# Working a ping run

The daily check-in and the hourly nudge are pings: each run only stamps itself and posts one line in its home thread. You, the coordinator, work that task's checklist (`hourly-nudge.md` or `daily-check-in.md` beside this file) the same turn. The checklists were written for a run that did the work itself; read them through this page.

- **Values.** Take them from the ping line: `{{kind}}`, `{{repo}}`, `{{parent_issue}}`, `{{toolkit_repo}}` and `{{report_dir}}`. `{{project}}` is the project name, `{{task_name}}` the task the line names, `{{task_slug}}` its run folder's name, and `{{checkin_name}}` and `{{nudge_name}}` are `<project>: Daily check-in` and `<project>: Hourly nudge`. A line tagged `[repo]` applies when repo is not `none`, `[no-repo]` when it is, `[parent]` when parent is not `none` and `[toolkit]` when repo is the Toolkit repo. A run found only by its stamp takes its values from the task's newest line in its home thread.
- **Project additions** in `{{report_dir}}/project-additions.md` are the project layer: read them first; they override the checklist where they differ.
- **You act, not report.** "This task", "this run" and "the report" mean you, working the run. Act on each finding the same turn, as **Acting on the nudge report** or **Acting on the check-in report** in `reference/periodic-runs.md` says. The REPORT section is what you post (its first line as the run's project-chat line, the rest only where the owner needs it) and the state file you keep (`nudge-state.md` or `state.md`); ping runs write no `latest.md` or `runs/` report.
- **Tool steps.** A step that starts `TOOL STEP (<tools>)` needs tools you may lack: a shell with a fresh Toolkit clone (`TK`), GitHub, or scheduled-task reads. Whoever runs one, you or a thread, first runs `touch ~/.toolkit-handoff-off` in its shell: the empty file turns Toolkit's handoff hook off for scheduled work (`reference/cloud-hook-parity.md`). Run it yourself when you have them. Otherwise send every such step of this run in one message to the task's home thread (or the thread the project additions name): the run UTC, the step numbers and this page. That thread runs them read-only and replies once with each step's lines and its own Run line (model and effort). Put the run UTC and the steps on the promise list; `.done` waits for that reply and your action on it.
- **Receipts.** Write `.relayed` after your project-chat line and `.done` after every step, each with its one line, beside the stamp, and read each back (**Task run relay** in `reference/recurring-tasks.md`).
