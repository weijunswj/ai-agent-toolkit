CHECKS
1. Binding, cheap compare first: `git ls-remote https://github.com/{{toolkit_repo}} refs/heads/main`. Read the BINDING line in project memory (MEMORY.md). If main's SHA equals the bound commit, the binding is current. Only if it differs: `git clone --depth 1 https://github.com/{{toolkit_repo}} TK` in your scratchpad and `git -C TK rev-parse HEAD:repo/CONTROLLER.md`. Blob different: STALE. Blob same, commit moved: current, note "commit moved to <commit7>" under **Toolkit:**. No BINDING line, no full blob in it, or a failed read: UNKNOWN with the reason.
[no-repo]   No repo and no BINDING line: write "**Toolkit:** binding none (no repo)" instead.
2. Threads: page through list_threads (follow next_cursor). Review every unresolved thread except task home threads (this one and any other the SCHEDULED TASKS line names). Read the latest messages (read_thread, limit 2) of each thread that is not working or has been idle 45 minutes or more.
   Stalled: (a) working with no activity for over 45 minutes; (b) blocked, failed or stopped while the thread still owes work; (c) its latest own message promises work ("I'll ...") with no activity for 45 minutes; (d) a promised result that never came.
   Mismatch: every open thread whose shown state differs from what is really pending (latest messages, memory, decisions made elsewhere), with the true state and the fix.
   Resolve candidates: list a thread only when all three hold, with the evidence for each: (1) its output is durably recorded (pushed, merged, in a report or file, or handed to a named thread); (2) its latest result was relayed to the owner in project chat (a coordinator post linking it, newer than the thread's latest message) or the owner replied in the thread after it; (3) no owner question or decision, open PR it owns or watches, or promised work is open. Reason FINISHED or SUPERSEDED (name what replaced it). Idleness is never a reason. Never list a task home thread. Say "unsure" rather than guess.
   Unrelayed: list_threads with state done for threads resolved in the last 24 hours or since the previous run. Flag any whose latest message is newer than the coordinator's latest project-chat post linking it, and any finished open thread whose result was never relayed.
3. Chat posts: list_threads leaves out top-level posts with replies, so page read_project_chat with limit 10 until there are no more. List unresolved posts that meet the three resolve conditions, and posts that need an owner action. Hidden reply: in post reply threads, open or closed, flag (a) an owner reply with no coordinator answer after it, and (b) a coordinator answer carrying a decision, question, owner action or change of plan with no one-line pointer to it in top-level project chat.
4. Remote Control: remote_control_status (no thread_id) lists the threads holding a session. Flag sessions not connected while their thread still owes work, and list as End RC candidates running sessions whose thread is finished or resolved.
