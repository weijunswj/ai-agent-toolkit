DAILY CHECK-IN ({{task_name}})
This check-in keeps the project's Toolkit base layer current: it finds what is out of date, including its own prompt and the library copy of the Projects skill (the guidebook), and tells the coordinator, which makes the change the same turn. It changes nothing itself apart from refreshing a guidebook copy the hourly nudge left stale (step 3). It is meant to be seen: every run reaches the owner as one line, so a silent day means it did not run.

CHECKS
1. Read /mnt/project-files/toolkit/web-controller-projects/VERSION and state it. Read project memory (MEMORY.md) and save it to a scratch file (MEMFILE). Read {{report_dir}}/state.md for the last check-in time (LAST; if missing, 24 hours ago) and its "plugin behind <version>" record.
2. Toolkit: `git clone --depth 200 https://github.com/{{toolkit_repo}} TK` in your scratchpad (always a fresh clone, never a stale local branch). Report main's short SHA and latest commit title. Scripts below run as `node TK/repo/scripts/<script>`.
3. GUIDEBOOK: run `node TK/repo/scripts/toolkit-projects-guidebook.cjs --check /mnt/project-files/toolkit/web-controller-projects`. `current <Version>`: "**Guidebook:** current <Version>". Otherwise take the newest commit time of `git -C TK log -1 --format=%cI -- repo/contracts/claude-projects/web-controller-projects repo/contracts/toolkit-local-bridge/version.json`. Under two hours ago: "**Guidebook:** <printed line>, left to the hourly nudge", unless the nudge's entry on the SCHEDULED TASKS line ends "stopped by owner <date>" or the nudge is not armed (step 9). Otherwise refresh it here: run it again with `--out` in place of `--check`, then `--check` once more, copy the printed lines under **Guidebook:**, and start the first line with "GUIDEBOOK MISSING: <reason>, <result> | " when the check printed `missing`, else "SKILL COPY STALE: <reason>, <result> | ", where <result> is "refreshed <Version>" (adding "block changed" when it printed BLOCK CHANGED) or "SKILL COPY FAILED <reason>".
   SKILL UPDATE: compare the guidebook's Version (after any refresh) with the `skill <Version>` on the BINDING line in memory. The guidebook's is newer: start the first line with "SKILL UPDATE: <old> -> <new> | ", so the coordinator reads the new SKILL.md, updates its task prompts where it says they changed (never one whose entry says stopped by owner) and records the Version.

No BINDING line, no full blob in it, or a failed read: "BINDING UNKNOWN: <reason> | ".
