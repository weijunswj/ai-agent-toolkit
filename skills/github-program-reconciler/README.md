# GitHub Program Reconciler

Implicitly discoverable skill for programme state on github.com only in this version: private per-child state documents in a private GitHub state store (compare-and-swap, fence and return IDs), one idempotent reconcile pass (`scripts/programme.cjs`) for native parent/sub-issue links, PR heads, required checks at the head and generated state blocks, the separate read-only decision-trace audit (`scripts/decision-trace-audit.cjs`) and truthful review records. The reconciler, its state documents, managed blocks and sub-issue links require `.github/toolkit-programme.json`; every `programme.cjs` command refuses without it. Toolkit-governed rules and their issue records are unchanged in 3.9.0. Repositories without the `TOOLKIT-GOVERNED-RULES` block get no governed issue writes, only coding-governance gates, subagents and portable skills; global rules still apply, including PRs after requested edits and task issues when the user asks to add one. Any session may dry-run and report; only the appointed controller holding the parent document runs `--apply`. Executors never apply, and never claim or take over the parent document. Only a newly appointed controller takes over the parent document, after posting its takeover record and verifying that the previous writer stopped. A gate successor the controller has assigned (for example G1 after G0) takes the child with `claim --issue <n> --role <gate> --takeover`. Only the parent holder consumes returns, records UAT and review, and sets DONE or RETIRED. The child holder may set release, candidate, blockers, next action, private and a non-final lifecycle, and submit returns; it never records acceptance or completion. It never closes, deletes or merges.

The skill is directly canonical; its document schemas are in `repo/contracts/programme-state/` in the Toolkit repository.
