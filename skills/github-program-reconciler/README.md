# GitHub Program Reconciler

Implicitly discoverable skill for programme state on github.com only: private per-child state documents in a private GitHub state store (compare-and-swap, fence and return IDs), one idempotent reconcile pass (`scripts/programme.cjs`) for native parent/sub-issue links, PR heads, required checks at the head and generated state blocks, the separate read-only decision-trace audit (`scripts/decision-trace-audit.cjs`), the read-only decision history the planning step (G0) runs before planning a child (`scripts/decision-history.cjs`, with the comment-tag parser in `scripts/decision-tags.cjs`) and truthful review records. The reconciler, its state documents, managed blocks and sub-issue links require `.github/toolkit-programme.json`; programme state commands refuse without it. Toolkit-governed rules and their issue records apply where that file, merged on the default branch, turns governance on (ENABLED), with or without a `TOOLKIT-GOVERNED-RULES` block in `AGENTS.md`. Repositories where it is not ENABLED get no governed issue writes, only coding-governance gates, subagents and portable skills; global rules still apply, including PRs after requested edits and task issues when the user asks to add one. Any session may run the preview (dry run) and report it. Only the appointed controller writes programme state: it holds the parent document and runs every writing command itself, including handing out work, returns, user testing, review and completion. A planning, build or review session it assigns (G0, G1 or G2) writes only its own checkpoint journal; helpers never write. It never closes, deletes or merges.

The skill is directly canonical; its document schemas are in `repo/contracts/programme-state/` in the Toolkit repository.

The parent has three managed headings: CURRENT, PROGRAMME GRAPH and AGENT CONTEXT. AGENT CONTEXT links the one comment whose topic is `Agent context`; with more than one such comment the block holds and names them. Its Decisions part links the parent's decision index comments, with `programme.cjs trace <n>` listing every decision by topic; the old DECISIONS block is removed on the next write. Open task pages follow one fixed order: PATH, then TASK (WHY with PROBLEM, FIX and IF WE SKIP, then DONE WHEN), then PLAN, then the PR GRAPH (each PR's title, number, status and merge commit; the tracked PR's status carries the gate and any owed UAT), then one AGENT CONTEXT line, then every other hand-written word under Title Case headings; a copy of the page is saved before its text is moved, a closed page that shows its finished status is frozen, and open PRs that name a task get PATH on top and STATUS with AGENT CONTEXT under the description (see [task and PR page layout](SKILL.md#task-and-pr-page-layout)). The Programme Graph has one row per task (`Task | Child # | Status | Waiting on | Last Updated (SGT)`) and names no PRs; each task page lists every PR found for its task. `TASK_IDLE` flags a task shown in progress that nothing is moving (a stale open PR does not count as moving), and `TASK_MERGED_OPEN` one whose PRs have all merged; both are the work queue, listed first and answered by action, never acknowledgement. Migration removes only the exact adjacent `## CURRENT` line. At 55,000 UTF-16 units it moves only the needed graph-row prefix to verified linked comments with an `Archived:` summary, with a hard body limit strictly below 60,000 and at most five new comments per issue per pass. Hand-written notes retain their bytes and order; only notes marked under one `## Archive` line move, and an agent adds that line with a holder order's `mark-archive` write, so nobody edits a page by hand. The whole page is first saved to the private store; on the parent the marked notes then move, unchanged, to linked comments, and on a task page one line links that saved copy in their place. Any doubt moves nothing and raises `ARCHIVE_SECTION_UNSAFE` (on a task page, `PAGE_LAYOUT_HELD`). `BODY_NEAR_LIMIT` and `BODY_TOO_LARGE` stay visible with exact section sizes until a complete verified redraw resolves them. Unchanged graph parts remain verified read-only across logins; changed, foreign or missing comments detach and get fresh verified replacements without freezing redraws. The registry rejects unknown fields and bounds excluded ids with a monotonic floor. See [managed blocks](SKILL.md#managed-blocks) for move order, registry trust, recovery and size diagnostics.

Completed tasks with no PR automatically recover a merged PR from body references, closing links and timeline cross-references in the same repository. The latest merge wins, with the higher PR number breaking an exact timestamp tie. Existing PRs are preserved; retired tasks are excluded.

Discovery batches twenty issues per link query within a budget that grows with the board. Refresh shares open and closed PR scans, lists every task PR, and flags PRs without a task, excluding the known bots. Incomplete evidence reports `PR_DISCOVERY_INCOMPLETE` and preserves recorded history and the complete-scan watermark. The normal guarded state writer still rechecks completed-task backfill eligibility. See [facts copied by refresh](SKILL.md#facts-copied-by-refresh) for lifecycle copying, native task adoption, child schema compatibility and findings waiting on the owner after 24 hours, and [attention](SKILL.md#attention) for answering them.

For the agent-at-close command, marker rules, governed gap scan and facts backstop, see [Closing comments](../toolkit-playbooks/closing-comments.md). Missing stories stay on attention until a marked story appears after the close.
