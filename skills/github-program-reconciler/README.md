# GitHub Program Reconciler

Implicitly discoverable skill for programme state on github.com only: private per-child state documents in a private GitHub state store (compare-and-swap, fence and return IDs), one idempotent reconcile pass (`scripts/programme.cjs`) for native parent/sub-issue links, PR heads, required checks at the head and generated state blocks, the separate read-only decision-trace audit (`scripts/decision-trace-audit.cjs`), the read-only decision history the planning step (G0) runs before planning a child (`scripts/decision-history.cjs`, with the comment-tag parser in `scripts/decision-tags.cjs`) and truthful review records. The reconciler, its state documents, managed blocks and sub-issue links require `.github/toolkit-programme.json`; programme state commands refuse without it. Toolkit-governed rules and their issue records are not changed by that file. Repositories without the `TOOLKIT-GOVERNED-RULES` block get no governed issue writes, only coding-governance gates, subagents and portable skills; global rules still apply, including PRs after requested edits and task issues when the user asks to add one. Any session may run the preview (dry run) and report it. Only the appointed controller writes programme state: it holds the parent document and runs every writing command itself, including handing out work, returns, user testing, review and completion. A planning, build or review session it assigns (G0, G1 or G2) writes only its own checkpoint journal; helpers never write. It never closes, deletes or merges.

The skill is directly canonical; its document schemas are in `repo/contracts/programme-state/` in the Toolkit repository.

The parent has four managed headings: CURRENT, PROGRAMME GRAPH, AGENT CONTEXT and COMMENT TRACE. AGENT CONTEXT links the one comment whose topic is `Agent context`, and COMMENT TRACE then leaves that comment out; with more than one such comment the block holds and names them. Open task pages follow one fixed order: PATH, STATUS and COMMENT TRACE, then PROBLEM, FIX, IF WE SKIP, DONE WHEN and NOT IN SCOPE, then More with every other hand-written word; a copy of the page is saved before its text is moved, and open PRs that name a task get PATH and STATUS on top (see [task and PR page layout](SKILL.md#task-and-pr-page-layout)). The Programme Graph shows one PR per row, the latest opened. `TASK_IDLE` flags a task shown in progress that nothing is moving. Migration removes only the exact adjacent `## CURRENT` line. At 55,000 UTF-16 units it moves only the needed graph-row prefix to verified linked comments with an `Archived:` summary, with a hard body limit strictly below 60,000 and at most five new comments per issue per pass. Hand-written notes retain their bytes and order; only notes the owner marks under one `## Archive` line move, unchanged, to linked comments after the whole page is saved to the private store, and any doubt moves nothing and raises `ARCHIVE_SECTION_UNSAFE`. `BODY_NEAR_LIMIT` and `BODY_TOO_LARGE` stay visible with exact section sizes until a complete verified redraw resolves them. Unchanged graph parts remain verified read-only across logins; changed, foreign or missing comments detach and get fresh verified replacements without freezing redraws. The registry rejects unknown fields and bounds excluded ids with a monotonic floor. See [managed blocks](SKILL.md#managed-blocks) for move order, registry trust, recovery and size diagnostics.

Completed tasks with no PR automatically recover a merged PR from body references, closing links and timeline cross-references in the same repository. The latest merge wins, with the higher PR number breaking an exact timestamp tie. Existing PRs are preserved; retired tasks are excluded and show `-` in the Programme Graph PR column.

Discovery batches twenty issues per link query and permits at most sixty additional discovery and detail requests per pass. Refresh shares open and closed PR scans, lists every task PR, and flags PRs without a task, excluding the known bots. Incomplete evidence reports `PR_DISCOVERY_INCOMPLETE` and preserves recorded history and the complete-scan watermark. The normal guarded state writer still rechecks completed-task backfill eligibility. See [facts copied by refresh](SKILL.md#facts-copied-by-refresh) for lifecycle copying, native task adoption, child schema compatibility and findings waiting on the owner after 24 hours, and [attention](SKILL.md#attention) for answering them.

For the agent-at-close command, marker rules, governed gap scan and facts backstop, see [Closing comments](../repository-agent-rules/repo-local/docs/agent-playbooks/closing-comments.md). Missing stories stay on attention until a marked story appears after the close.
