# GitHub Program Reconciler

Implicitly discoverable skill for programme state on github.com only: private per-child state documents in a private GitHub state store (compare-and-swap, fence and return IDs), one idempotent reconcile pass (`scripts/programme.cjs`) for native parent/sub-issue links, PR heads, required checks at the head and generated state blocks, the separate read-only decision-trace audit (`scripts/decision-trace-audit.cjs`) and truthful review records. The reconciler, its state documents, managed blocks and sub-issue links require `.github/toolkit-programme.json`; every `programme.cjs` command refuses without it. Toolkit-governed rules and their issue records are not changed by the binding. Repositories without the `TOOLKIT-GOVERNED-RULES` block get no governed issue writes, only coding-governance gates, subagents and portable skills; global rules still apply, including PRs after requested edits and task issues when the user asks to add one. Any session may run the dry-run reconcile or show and report it. Only the appointed controller writes programme state: it holds the parent document and runs every writing command itself, including gate assignments, returns, UAT, review and completion. An executor it assigns (G0, G1 or G2) writes only its own checkpoint journal; helpers never write. It never closes, deletes or merges.

The skill is directly canonical; its document schemas are in `repo/contracts/programme-state/` in the Toolkit repository.
